# FHE+ML 与区块链的关联性分析

> 日期：2026-04-13
> 核心问题：密文下机器学习跟区块链有没有必然关联？

## 结论：关联性弱，不建议强行结合

### 密文 ML 和区块链是两个独立问题

```
密文 ML（SEAL/HElib/Concrete ML）解决的问题：
→ "在不看数据的情况下做推理"
→ 应用：医院间联合建模、银行间风控、隐私保护的云端推理
→ 不需要区块链，中心化服务器就能跑

区块链解决的问题：
→ "在不信任对方的情况下达成共识"
→ 应用：去中心化金融、去信任交易
→ 不需要 ML
```

把它们强行绑在一起的问题：

1. **性能矛盾**：FHE ML 推理本身就很慢（逻辑回归 ~秒级，小神经网络 ~分钟级），放到链上/协处理器更慢
2. **必要性存疑**：如果信用评分模型是协议方自己部署的，模型参数加密对谁隐藏？对协议方自己？
3. **Concrete ML 跟 fhEVM 是两套体系**：Concrete ML 编译出的 FHE 电路是 Python/C++ 端的，不能直接部署为 Solidity 合约

### 真正有关联的场景极少

| 场景 | 区块链必要？ | FHE ML 必要？ | 两者同时必要？ |
|------|:-:|:-:|:-:|
| 链上信用评分 | 是 | 不一定——线性公式够用 | **弱** |
| 联邦学习协调 | 可选（用于激励） | 是 | **弱** |
| 隐私 AI 推理市场 | 是（支付+验证） | 是 | **中等，但很早期** |
| 加密预言机 | 是 | 可选 | **弱** |

### 对赏金活动的判断

赏金主题是 **"Confidential Onchain Finance"**，核心是 **金融 + 隐私 + 链上**。

- ML 不是必要条件
- 评审标准里没有"AI/ML"关键词
- 硬塞 Concrete ML 反而可能让评委困惑："这跟链上金融有什么关系？"

## 建议

保持现有方案（4 合约 + 前端），把精力放在：
1. 打磨演示流程
2. 完善文档叙事（公开信誉 vs 加密信用的区分）
3. Sepolia 部署
4. 2 分钟视频

FHE+ML 作为独立项目探索，不跟赏金混在一起。
